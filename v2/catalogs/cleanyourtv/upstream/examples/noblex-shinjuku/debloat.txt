# Noblex NoblexTV (Skyworth-built, codename shinjuku, MediaTek m5621), Argentina, Android TV 11 (API 30), firmware RTO9.230812.001
# armeabi-v7a (4x Cortex-A53 @ 1.3 GHz, 32-bit userspace), UI at 1280x720, about 0.9 GB RAM, ro.config.low_ram=true.
# Classic Android TV home, not Google TV: the stock launcher is com.google.android.tvlauncher.
# Same firmware family as examples/panasonic-th-40hs550k (shibuya); this list starts from that one.
#
# Stock launcher:  com.google.android.tvlauncher
# Live TV app:     com.mediatek.wwtv.tvcenter  (Live TV and the input panel; keep it)
# Never disable any com.mediatek.* package except testpq: they are the tuner, input and HDMI stack.
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/noblex-shinjuku/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/noblex-shinjuku/debloat.txt
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Disabled before this debloat, so not listed (restore.sh would turn them ON):
# com.google.android.marvin.talkback, com.google.android.videos.
#
# Status: disabled in three batches on one TV on 2026-10-21, with a Home screenshot after each batch, then
# launcher/ installed as Home, a reboot and a standby/wake check. Hours of use when submitted, not days:
# treat it as a starting point.
#
# Quirks on this firmware, all checked on the TV:
# - Disabling com.smartdevice.leanbacklauncher.customizer removes the Inputs and Wi-Fi icons from the stock
#   launcher's top bar (same as partnercustomizer on the Panasonic); irrelevant once launcher/ is home.
# - disable.sh skips com.mediatek.wwtv.mediaplayer (it asks for TV_INPUT_HARDWARE); left on.
# - The remote's power button suspends: waking returns to the app that was on screen. Only a cold boot
#   (reboot, power cut) comes up on Live TV (tvcenter resumes the last source).
# - About 0.9 GB of RAM and the cause of the lag when switching apps: after a reboot Netflix (~120 MB),
#   Max, YouTube and Play Store start on their own. This list plus launcher/ took MemAvailable from about
#   230 MB to about 300 MB; `cmd appops set <pkg> RUN_ANY_IN_BACKGROUND ignore` on the streaming apps took
#   it to about 330-360 MB. The apps still open normally; `... allow` undoes it, restore.sh does not.
# - The load average reads ~95 at idle with the CPU 80% idle: about 98 MStar driver threads (DMX_Filt_Task,
#   VMon_Task...) sit in D state. Not real load.
