# Redmi TV (MiTV-MFTP0, codename alita; China-market firmware), Android 9 (SDK 28),
# firmware 23.2.10.6129, MediaTek/MStar m7642, MemTotal 2.6 GB, 1080p UI (320 dpi).
# Stock launcher: com.mitv.tvhome 3.49.1601 (HOME activity .MainActivityUserMode) - KEEP IT ENABLED,
# see "Home" below.
# Disabled on 2026-10-21 in two batches; the owner checked Home and the voice remote after each batch,
# and Xiaomi settings and a streaming app after the first. Package states were read back after a
# standby cycle (all still disabled). After a full reboot (not standby) the owner reported the
# replacement launcher still Home and no startup ad; ADB closes at reboot, so package states were not
# read again after it. Not yet lived with for several days.
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/redmi-mitv-mftp0/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/redmi-mitv-mftp0/debloat.txt
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Notes from this firmware:
# - ADB: Settings -> About -> press OK on 产品型号 (product model) 7 times to unlock developer mode,
#   then Settings -> 账号与安全 (Account & Security) -> ADB 调试 -> 允许. Network ADB (port 5555) closes
#   on every reboot; turn it on again there after each power cycle. Standby is not a reboot.
# - `pm disable-user --user 0` is accepted for the shell user (unlike MiTV-ANTL0, which needs `pm hide`).
# - Home: the framework filters third-party HOME candidates by a package-name allowlist, the same
#   mechanism as MiTV-AETP0 (services.vdex has isThirdpartyHomeAllowed and
#   APP_WHITELIST_ALLOW_THIRDPARTY_HOME; the list is /data/system/mitv_security_center.xml, not readable
#   from the shell). The standard com.gathin.tvhome build installed and opened, and
#   `cmd package set-home-activity` printed Success, but HOME still resolved to com.mitv.tvhome.
#   The opt-in application-ID build from docs/devices/xiaomi-mitv-aetp0-dofus.md
#   (`./gradlew assembleRelease -PlauncherApplicationId=com.ts.launcher`) became Home with
#   com.mitv.tvhome still enabled, and stayed Home after a full reboot. Do not run
#   launcher/build-and-install.sh with its defaults here: it would disable com.mitv.tvhome, and
#   disabling the stock launcher leaves no allowed Home. Use the manual commands in that doc.
# - Settings: android.settings.SETTINGS and android.settings.WIFI_SETTINGS resolve to nothing; the
#   launcher's Settings pill falls back to com.xiaomi.mitv.settings/.entry.MainActivity, which opened.
# - App grid: the streaming apps declare LEANBACK_LAUNCHER and show up; Xiaomi settings, weather and
#   TV Manager are LAUNCHER-only. com.mitv.alarmcenter declares LEANBACK_LAUNCHER (hide it with
#   hidden_apps if you don't want a 定时提醒 tile).
# - Inputs: com.mediatek.tvinput registers HDMI HW5-HW8, AV HW2, component HW3, VGA HW4 and tuners
#   HW0/HW1. Nothing was plugged in, so switching from the launcher's Inputs menu was not tested.
# - Startup ad: `settings put system boot_ad_switch 0` (it was null before) removed it, checked after
#   a full reboot with stock launcher 3.49.1601. boot_ad, boot_ad_sound_enable and boot_ad_switch_show
#   were already 0 and did not stop the ad. Undo: `settings delete system boot_ad_switch`.
#   See docs/devices/xiaomi-l43m7-ea-antl0.md for the same key on an older launcher.
# - Screenshots: `screencap` exits 1 with a 0-byte file while PatchWall's home is on screen (it shows a
#   sideband video layer); it works over the replacement launcher, settings and the screensaver.
# - com.gitvdemo.video is 银河奇异果 (GITV's licensed iQIYI app, label checked with aapt), a streaming
#   app, not a promo reel. Kept here.
# - com.mitv.care ("adcare") is disabled by the factory already.
#
# Deliberately NOT disabled:
# - mitv.service, com.xiaomi.mitv.tvplayer, com.mediatek.* (inputs, tuner), com.xiaomi.mitv.settings,
#   com.xiaomi.mitv.systemui, com.sohu.inputmethod.sogou.tv (the only keyboard), com.android.bluetooth,
#   com.xiaomi.account, com.xiaomi.mitv.appstore, com.xiaomi.mitv.mediaexplorer, com.mitv.mivideoplayer,
#   com.mitv.videoplayer, com.mitv.codec.update, com.xiaomi.mitv.debug (purpose unclear).
# - mediatek.factorymenu.ui and com.mstar.android.media.tests are factory tools: never start them.
# - com.mitv.screensaver: the stock flip-clock screensaver stays until another one is selected.
# - com.xiaomi.mitv.tvpush.tvpushservice: besides push it carries
#   com.xiaomi.mitv.getwhitelist.GetInstallerWhiteList, and this firmware has an install blacklist
#   (pi_config in Settings.System). Not disabled, so app installs were not put at risk.
# - com.xiaomi.mitv.smartpanel: MiTV-ANSP0 disabled it, MiTV-MFFU0 says it is the Menu-button panel. Kept.
# - Kept by this owner's choice: voice remote (com.xiaomi.voicecontrol, com.xiaomi.wakeupservice,
#   com.xiaomi.mitv.tvmanager, com.mitv.alarmcenter), casting (com.xiaomi.miplay,
#   com.xiaomi.mitv.smartshare, com.duokan.airkan.tvbox, com.xiaomi.wfdsinkhelperservice,
#   com.xiaomi.mi_connect_service), firmware updates (com.xiaomi.mitv.upgrade, ~47 MB resident),
#   payments (com.xiaomi.mitv.pay, com.xiaomi.mitv.payment), karaoke (com.xiaomi.mitv.karaoke.service),
#   the business-TV apps (com.xiaomi.eetv.exhibition, com.xiaomi.eetv.tvmeetingmanager), all streaming apps.
#
# Resident memory of the processes this list stops, measured before the change (dumpsys meminfo PSS):
# shoplugin 45 MB + 19 MB, Mi Home 18 MB, TV analytics 13 MB, tvqs 12 MB, statistic 8 MB,
# gallery 8 MB, cloud control 7 MB; about 130 MB together. PatchWall itself (~250 MB) keeps running.
