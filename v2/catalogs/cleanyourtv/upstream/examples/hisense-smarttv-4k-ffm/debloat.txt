# Hisense SmartTV 4K FFM (device huangshan, MediaTek), Android TV 10, firmware QTG3.200902.001
# Security patch 2023-02-05. Sold in Latin America; the Android model string is "SmartTV 4K FFM".
# The same device and build ships in the USA as the Hisense U9DG (75" Dual-Cell ULED, 2021), with a
# US preload set: the "US (U9DG)" groups below. 2 GB RAM, armeabi-v7a (32-bit userspace), 7.7 GB /data.
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/hisense-smarttv-4k-ffm/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/hisense-smarttv-4k-ffm/debloat.txt
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# WARNING, read before applying: a first version of this list that also disabled
# com.hisense.tv.smartsense, com.vt.tv.smartsense.ui and com.vt.tv.aiot sent the TV to Android
# Recovery on the next boot ("Can't load Android system. Your data may be corrupt"). "Try again"
# booted normally and tools/restore.sh undid everything. Which of the three was the cause is not
# confirmed, so all three are left out below. Never pick "Factory data reset" on that screen
# before trying "Try again".
# This list was then applied in seven groups with a reboot after each: no crashes, normal boot.
# If you experiment with more packages, reboot after each small group, and wait ~15 s after
# pm disable-user before rebooting: rebooting immediately lost the change on this TV.
# US (U9DG), 2026-10-21: the Hisense, Google and US groups applied in five batches with a reboot after
# each, OTA kept: normal boot every time, all 7 inputs (HDMI 1-4, composite, two tuners) still
# registered, HDMI switching from the launcher and Chromecast work. Fresh on that set, not yet lived
# with for weeks.
#
# ADB: turning USB debugging on opens port 5555 directly (no Wireless debugging pairing);
# ro.adb.secure=1, so the TV asks "Allow USB debugging?" on first connect.
# Input button (U9DG Bluetooth remote, Vendor_000d_Product_3838.kl): scancode 220 = KEYCODE_TV_INPUT,
# which the Live TV app and the launcher's InputKeyService turn into com.android.tv.action.VIEW_INPUTS.
# Nothing on this firmware answers that action once tvlauncher is disabled (no global_keys.xml, no
# vendor input picker), so the button does nothing until the launcher answers it itself:
# handle_view_inputs in config.json in this folder (TV_HOST=<tv ip> tools/theme.sh
# examples/hisense-smarttv-4k-ffm), with INPUT_KEY_SERVICE=1 at install.
# setupwraith (com.google.android.tungsten.setupwraith) owns the Wi-Fi saved at setup but does not
# claim HOME on this firmware, so it stays enabled; launcher/build-and-install.sh worked unchanged.
#
# Keep: com.mediatek.* (including com.mediatek.wwtv.tvcenter, the Live TV and HDMI app),
# com.hisense.tv.hitvinput, com.hisense.tv.smartservice, com.vidaa.persistent.service,
# com.hisense.tv.customerlauncher. HDMI-CEC and the inputs keep working with this list.
# Stock launcher: com.google.android.tvlauncher (the default in restore.sh).
# Already disabled at the factory: net.vidaatv.android.tv, Pandora, Vudu, Play Games (and on the
# U9DG also Google TV movies, YouTube Music, the Hisense browser and the calendar provider).
