# Gadnic PROJ100W (rebranded Skyworth HP4609-Skyworth, built-in "4K Google TV Stick"), Argentina.
# manufacturer SkyworthDigital, device YYT, Amlogic (ro.board.platform HP46B), ~1.9 GB RAM.
# Google TV 14 (API 34), build UKG3.250518.001/C3.2.5_20260104. Same stick/chip family as
# examples/wanbo-x5-pro and examples/byintek-t5-max; this list follows theirs closely.
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/gadnic-proj100w/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/gadnic-proj100w/debloat.txt com.google.android.apps.tv.launcherx
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Wi-Fi/setupwraith gotcha confirmed again on this unit, same as wanbo-x5-pro and byintek-t5-max:
# dumpsys wifi showed cname=com.google.android.tungsten.setupwraith (the network saved at first
# setup), so disabling it or launcherx first drops Home to setupwraith's RecoveryActivity, which
# restarts every ~60 ms. Fix: on the projector, Settings > Network & Internet > forget the saved
# Wi-Fi network, then rejoin it from there (not from a script) - this re-saves it under
# android.uid.system. Only then disable setupwraith and launcherx and set the new launcher's Home.
# disable.sh's own guard will skip setupwraith automatically while it still owns the network.
# Disabling setupwraith gives Home back but breaks casting (Chromecast built-in); comment out its
# line below if you want to keep casting.
#
# ADB notes for this stick: USB debugging never opened port 5555 directly; paired once over
# Wireless debugging (stock `adb pair`/`adb connect`), then `adb tcpip 5555` got a plaintext port
# tools/tv.py can use (adb_shell has no STLS/TLS support, and this firmware answers wireless
# debugging's port in TLS only). `adb tcpip 5555` and the Wireless debugging toggle both reset on
# every reboot; re-pair (or re-connect if still trusted) each time, then re-run `adb tcpip 5555`.
#
# com.android.devicelockcontroller exists but pm disable-user is refused on this firmware family
# (confirmed on wanbo-x5-pro too); not attempted here.
#
# Done 2026-10-21, one unit, same session (not lived with for days): this list applied, then the
# DreamOS template installed as Home (dock: YouTube, Netflix, Disney+, Prime Video), screensaver
# switched to the launcher's clock (`settings put secure screensaver_components
# com.gathin.tvhome/.ClockDream` - com.google.android.apps.tv.dreamx itself was left enabled,
# just no longer invoked), dock apps compiled with `cmd package compile -m speed -f`, and animation
# scales set to 0.5. Reboot-checked: Home stayed com.gathin.tvhome, Wi-Fi stayed on
# android.uid.system. Idle metrics (REBOOT=1 metrics.sh, 150 s settle), same TV: MemAvailable 543 ->
# 748 MB, swap used 456 -> 373 MB, CPU idle 281/400 -> 393/400. The debloat batches alone (before
# the launcher) only moved CPU idle 281 -> 310/400; the launcher and screensaver swap accounted for
# most of the idle-CPU win, not the debloat.
# Owner's choices: voice assistant unused -> katniss and TalkBack disabled. YouTube, Netflix and
# other streaming apps used -> kept enabled, not touched.
