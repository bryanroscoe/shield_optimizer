# Known quirks on this firmware:
# - screencap -p on stdout is corrupted by MediaTek log lines ("Init wrapper sys mutex successful").
#   Save to /sdcard and pull the file instead.
# - Screenshots are empty while Netflix, an HDMI input or the ttvs update screen is shown.
# - Storage: /data was 93% full (190 MB free) and sys_storage_threshold_percentage is 10, so about 270 MB
#   is reserved and pm install failed with "Requested internal only, but not enough space".
#   `pm trim-caches 4G` freed about 100 MB, not enough. Uninstalling user-installed apps the owner did not
#   want (Crossy Road, Max, Crunchyroll, DirecTV GO) freed about 470 MB. Those are not in this list.
# - INSTALL_FAILED_VERIFICATION_FAILURE is not a firmware sideload block here:
#   1) with this little RAM, the com.tcl.guard memory manager (TGuard) kills com.android.vending in the
#      middle of verification (logcat "tguard-kill-systemApp"), which fails the install. Force-stop
#      apps / `am kill-all`, or install right after a reboot.
#   2) installing only base.apk of a split app is rejected by Play Protect for the missing splits; that
#      is not a valid sideload test. The 272 KB launcher APK installed fine.
# - com.tcl.guard runs as a persistent system process (*PERS*, uid 1000). `pm disable-user` succeeds but
#   the process still starts at boot, so the disable does not stop the memory manager. It stays in the
#   list for the UI/cleaner parts.
# - Opening Settings' About page directly (am start -a android.settings.DEVICE_INFO_SETTINGS) and then
#   Software update crashes TvSettings (ClassCastException AboutActivity -> MainSettings in
#   com.tcl.android.tv.settings.update.SoftwareUpdateFragment). Enter through the main Settings menu.
#   Not caused by the debloat.
# - com.tcl.ttvs is the firmware updater (also BI and Alexa), not text-to-speech. Keep it.
#   com.tcl.messagebox carries an org.tcl.ttvs receiver; it was disabled here and the updater still
#   opened and showed the check screen.
