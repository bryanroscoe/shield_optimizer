# Wired native quit development path

This slice stacks on approved PR178 `af3afc9aa71a05dce64d9e03a95d2890483c5ef8`. It reuses that coordinator and its native preference/resource adapters. It adds no second simulation controller. The `dev-exit` Cargo feature is opt-in and compilation is rejected without debug assertions. The ordinary app entry point, production identifier, updater flow and command table are unchanged when the feature is absent. No installer/tag/release is produced.

From `v2/`, start `npm run dev -- --host 127.0.0.1 --port 1420`, then `cargo run -p shield-optimizer-v2 --features dev-exit --bin shield-optimizer-v2`. The native window opens `/dev/native-exit`. The development application identifier is `com.shieldoptimizer.native-exit-development`; native preferences use only `exit-settings-v1.json` under a separate `ShieldOptimizerDevelopmentExit` data directory. `SHIELD_DEV_EXIT_DATA_DIR` optionally chooses a native-owned development data root; it is never a frontend argument.

## Functional development behavior

The real DriverFactory owns the same Controller as the native coordinator. Saving Leave/Auto serializes validate → fixed-path persistence → preference update without replacing that controller or discarding existing permits. Confirmation uses the reviewed owned transaction. Native callbacks first prevent the native event, then enqueue into a FIFO owned mailbox without taking the coordinator/store lock. UI commands use that same mailbox, preserving ordering with Save/Confirm while persistence is blocked. Dropping an IPC reply waiter does not remove its owned message or strand committed shutdown. Tokens are session/attempt strings, and native Confirm/Cancel validate them. Cancel leaves preferences and admission unchanged.

Normal main-window CloseRequested is held only when it is the last webview window, preserving the pinned app's last-window-to-application-quit behavior. Other window closes are left to Tauri. Native ExitRequested/menu quit routes to the same coordinator and reveals the native settings/prompt or retained failure/pending-delivery route even after navigation, with repeated requests coalesced into one owned runner. No hide-to-tray or macOS keep-alive behavior is introduced. Native close/menu acceptance on every OS remains a review/release gate; the mock loop is not that acceptance.

After logical operations drain, AppResources drains the actual AppState.remote_sessions map, starts each existing core close_local future independently, and observes every join. It does not call drop_all_remote_sessions, forward removal or any device-side cleanup. Controller leases must report completion before final delivery. Cleanup failure/deadline retains a visible failure and requires explicit exit without another stop attempt.

Final delivery is scheduled on the native main thread. Its helper consumes only the exact authorized token, calls cleanup_before_exit, then immediately calls the non-returning process exit with status zero. No intervening await or Tauri API is used. Failed scheduling leaves the completed token recoverable for retry. The helper's fake effects test verifies cleanup-before-exit and one-shot delivery; tests never call the real process-exit implementation.

Always stop is explicitly disabled in the UI and rejected natively before persistence/commitment. A stored Stop value falls back to unremembered Leave without rewriting it. The injected native Stop implementation has no command or targeting code and is unreachable through the accepted settings/actions. Auto honestly leaves shared ADB running because ownership is unknown.

## Isolation and updater boundary

This first development app deliberately rejects every device/installation/network-scan command and constructs NoAdbDriver. It still uses the real AppState, factory controller, store and map teardown. There is no executable ADB path in this entry point. Only dev_exit_action is registered. Updater and process plugins are not registered, so direct frontend install/restart capabilities cannot bypass coordination. The shared layout skips ordinary updater initialization on this development route. This is functional native quit with safe Leave/Auto, not a claim of production device/update integration.

Pinned local source audit: opener 2.5.4, dialog 2.7.1, updater 2.10.1 and process 2.3.1 register no RunEvent callbacks. The development builder registers none of those plugins. The app has no custom Exit callback to preserve. Tauri 2.11.2 calls plugin RunEvent callbacks before its application callback; direct final delivery skips final run-event emission and uses its public cleanup_before_exit instead. Extending the plugin set or production entry point requires repeating this audit.

Updater activation remains separate: native-owned download must return Ok(bytes) after signature verification, then commit/drain and close the actual map before installation. Windows retains the default installer cleanup immediately before installer/process exit. Elsewhere install is followed by request_restart without premature framework cleanup. Direct frontend installation/restart capabilities must be removed when that flow is activated. No update/download/install/restart operation is run here.

## Evidence and remaining gates

New checks exercise the actual generated Tauri handler, genuine pinned MockRuntime CloseRequested/ExitRequested events, real fixed-path persistence, stale/unavailable Stop actions, preserved factory permits, repeated quit coalescing, and one-shot final-effect ordering. A populated real RemoteInputSession in AppState is created only from an injected fake driver, owned sleep process and loopback socket; teardown empties the map, closes the socket and reaps the lease without any additional fake ADB cleanup call. No real ADB binary or TV is used.

The native mock event test uses a checked sentinel unwind to terminate the pinned mock loop after exit prevention; it does not grant an unrelated event an exit bypass. Real platform events/menus, final process delivery, resource ownership under OS termination, and the future production updater/targeting path remain independent review/physical acceptance gates.

An earlier development build was launched only to show the first-quit prompt, with workspace-local data and no confirmation. The temporary prompt-on-start recording helper is not retained in this slice. Native window capture failed with `could not create image from window` despite a positive screen-capture preflight. Accessibility was unavailable and no permission was requested. No native UI video is claimed; only the task-owned app and loopback server were stopped afterward. Visual acceptance remains pending.

Local macOS validation: all eleven wired adapter checks passed within the combined E2E/development backend run (455 core and 180 desktop tests passed, one live-device test ignored). The unchanged default/E2E path passed 455 core and 169 desktop tests, with the same live-device skip. Strict all-targets Clippy passed for both configurations; formatting and diff checks passed. Svelte reported zero errors/warnings and the ordinary frontend build passed. Each Rust CI matrix job explicitly runs the dev-exit-only wired filter and strict lint on Linux, macOS and Windows. No cross-platform or physical native-exit acceptance is implied by these local results.

The blocked-store native-loop regression cancels the IPC waiter, holds persistence across a real CloseRequested callback, and proves that callback returns before the store is released; the owned Save still commits before queued quit. Recovery regressions inject cleanup and final-delivery failures, navigate away, and issue native quit, verifying the same failure/token/sequence is restored without repeating delivery, teardown or admission.
